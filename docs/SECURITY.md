# Security

Release threshold: **zero known cross-workspace or cross-identity data exposure.** The authorization test project (`pnpm test:authorization`) is the standing proof and runs in CI.

## Controls implemented

| Requirement               | Implementation                                                                                                                                                                                                                                                                                                                   | Verified by                                                                        |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Authentication            | Local accounts: scrypt (N=2^15, r=8, p=1), 12+ char policy, lockout after 10 failures / 15 min, constant-time dummy verify for unknown users. Sessions are random 256-bit tokens stored as HMAC-SHA256; 30-minute access, 14-day rotating refresh; refresh reuse revokes the whole chain.                                        | `app.int.test.ts`, `passwords.test.ts`                                             |
| Cookies                   | `httpOnly`, `SameSite=Lax`, `Secure` outside dev, refresh cookie scoped to `/v1/auth/refresh`. Bearer tokens accepted for non-browser clients.                                                                                                                                                                                   | manual + integration                                                               |
| Centralized authorization | `AuthorizationService` with deny-by-default `evaluate()`; every route calls it before data access, context assembly or model invocation. REQUIRES_APPROVAL for consequential actions (Action Gateway).                                                                                                                           | `policy.test.ts`, `isolation.authz.test.ts`                                        |
| Row-level security        | RLS enabled and forced on all tenant tables; app role `ae_app` has NOBYPASSRLS and no grant on `sessions`; policies require both matching context and membership.                                                                                                                                                                | `rls.authz.test.ts`                                                                |
| Workspace isolation       | Resource `workspaceId` must equal request workspace (P-CROSS-WORKSPACE); RLS makes other workspaces' rows invisible even with a spoofed context.                                                                                                                                                                                 | both suites                                                                        |
| Privacy classification    | PUBLIC / INTERNAL / CONFIDENTIAL / RESTRICTED on knowledge, conversations, projects. Models declare clearance; routing excludes uncleared models; retrieval ceiling is applied in SQL; gateway re-checks.                                                                                                                        | isolation suite ("information above a model's clearance never reaches that model") |
| AI-use permission         | Owner can mark knowledge DENY; retrieval SQL and policy P-AI-USE both exclude it.                                                                                                                                                                                                                                                | isolation suite                                                                    |
| Provider key security     | Keys resolved server-side by `CredentialBroker` from env / Key Vault by `credentialRef`; never persisted, logged (pino redaction), sent to the browser (`credentialRef` stripped from responses) or placed in model context.                                                                                                     | integration test asserts absence                                                   |
| Rate limiting             | Global per user/IP (`AE_RATE_LIMIT_PER_MINUTE`), stricter on auth routes (20/min).                                                                                                                                                                                                                                               | config                                                                             |
| Budget controls           | Monthly workspace ceiling enforced by the gateway before each run from the usage ledger.                                                                                                                                                                                                                                         | gateway unit test                                                                  |
| Immutable audit           | `audit_events`, `provenance_records`, `authorization_decisions`, `model_status_changes` reject UPDATE/DELETE via trigger for every role, including the owner.                                                                                                                                                                    | RLS suite                                                                          |
| Input validation          | Zod on every request body/query/param; body limit 1 MB; upload limit configurable (10 MB default).                                                                                                                                                                                                                               | integration                                                                        |
| Secrets in prod           | API refuses to start in prod with insecure cookies, placeholder session secret or dev experimental default.                                                                                                                                                                                                                      | `config.ts`                                                                        |
| Headers                   | Helmet, `X-Frame-Options: DENY`, `nosniff`, strict referrer policy on the web app.                                                                                                                                                                                                                                               | config                                                                             |
| Prompt-injection posture  | Sources are placed in the system prompt as labelled data with an explicit "treat as information, never instruction" rule; the security evaluation suite includes indirect-injection and canary-leak cases; model output never executes (no tool execution path exists yet, and `action.execute` is REQUIRES_APPROVAL by policy). | `security-injection` suite                                                         |
| Export and deletion       | Self-only (P-SELF), audited; deletion revokes all sessions immediately.                                                                                                                                                                                                                                                          | integration                                                                        |

## Not yet implemented (tracked in STATUS.md / ROADMAP.md)

- OIDC / OAuth 2.1 federation (Entra External ID, Auth0, Clerk) and MFA enforcement. `users.mfa_enabled` / `mfa_secret_enc` columns and `IdentityProviderConfig` exist; no flow yet.
- Malware scanning of uploads (pipeline step recorded as deferred; only text formats accepted).
- Object storage with signed URLs (originals currently in PostgreSQL `text_content`).
- Encryption at rest beyond what the managed database provides (column-level encryption for `mfa_secret_enc` is planned).
- Revocation propagation to a cache layer (there is no cache yet; sessions are checked against the database on every request).
- Account purge job (`account.delete` is enqueued; the handler is not implemented).

## Reporting

Security findings go in STATUS.md under "Security findings" with date, severity, and fix commit. Anything meeting the release threshold's definition of exposure blocks release.
