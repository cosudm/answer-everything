# Deployment

Three environments, one Terraform module, one set of container images promoted by tag.

|                              | DEV                        | UAT                            | PROD                                                                    |
| ---------------------------- | -------------------------- | ------------------------------ | ----------------------------------------------------------------------- |
| Purpose                      | Integration, demos         | Acceptance with real providers | Customers                                                               |
| `AE_ENV`                     | dev                        | uat                            | prod                                                                    |
| Experimental models default  | off (opt-in per workspace) | off                            | off; API refuses to start if `AE_DEFAULT_ALLOW_EXPERIMENTAL=true`       |
| LOCAL deployments (dev stub) | allowed                    | refused by gateway             | refused by gateway and skipped by seed                                  |
| Database                     | B1ms, public endpoint      | D2ds, public endpoint          | D4ds, zone-redundant HA, private endpoint, 35-day geo-redundant backups |
| Replicas                     | 1                          | 1                              | api 2–10, web 2–6, worker 1–4                                           |
| Cookies                      | `Secure`                   | `Secure`                       | `Secure` (enforced)                                                     |
| Promotion                    | automatic on `main`        | manual, reviewed               | manual, reviewed, change record                                         |

## Images

`infra/docker/{api,worker,web}.Dockerfile`, built from the repo root. The API image carries `dist/server.js`, `dist/migrate.js`, `dist/seed.js`, the SQL migrations and `config/models.seed.json`; its entrypoint applies migrations and seeds the registry before serving, and any arguments replace that (`docker run ae-api node dist/migrate.js status`). CI builds and smoke-tests the images on every push and pull request, and pushes `ghcr.io/<org>/answer-everything-{api,worker,web}:dev` from `main` when the repository variable `PUBLISH_IMAGES` is `true`.

## First deploy of an environment

```bash
cd infra/terraform/envs/<env>
terraform init -backend-config=backend.hcl
terraform apply
# put provider keys in Key Vault under the credentialRef names (ANTHROPIC-API-KEY, ...)
# run once from CI or an operator shell inside the api image:
AE_MIGRATIONS_DIR=/app/migrations node dist/migrate.js migrate
AE_MODEL_SEED_PATH=/app/config/models.seed.json node dist/seed.js
```

Migrations are forward-only, checksum-verified, each in its own transaction. Roles `ae_app` and `ae_identity` are created by the runner from `AE_DB_APP_PASSWORD` / `AE_DB_IDENTITY_PASSWORD`.

## Configuration

Everything is environment variables (see `.env.example`). Secrets come from Key Vault through Container Apps secret references; `AE_SESSION_SECRET` is generated by Terraform and stored there. Provider keys are never in Terraform state.

The web image is built with `NEXT_PUBLIC_API_URL` baked in; the API's `WEB_PUBLIC_URL` must match the web origin for CORS with credentials. In production, front both with the same parent domain (`app.` and `api.`) so cookies behave as same-site.

## Observability

- Structured JSON logs (pino) to stdout → Log Analytics.
- `/metrics` in Prometheus format (requests, model runs, tokens, cost, authorization decisions, jobs, latency histogram).
- OpenTelemetry API is wired; set `OTEL_EXPORTER_OTLP_ENDPOINT` / `APPLICATIONINSIGHTS_CONNECTION_STRING` and add the SDK bootstrap to `apps/api/src/server.ts` to export spans (roadmap).
- `/health` reports database reachability and whether an embedding model is configured.

## Rollback

Container Apps revisions: re-point traffic to the previous revision. Database migrations are additive in the MVP; a rollback that needs schema changes gets a new forward migration.

## Local

`docker compose up` or `pnpm dev` (see README). `pnpm db:reset` rebuilds the schema and refuses when `AE_ENV=prod`.

## Cloudflare (Workers + Containers)

The fast path to a hosted environment: one Worker fronting the API and web containers on a single origin, built and deployed by Workers Builds on every push to `main`. It needs no secrets to come up: without `DATABASE_URL` the API container runs on labelled demo storage (a container-local PostgreSQL that is erased on restart). Setting the single secret `DATABASE_URL` switches it to a durable database. See `apps/cloudflare/README.md` for the dashboard steps and ADR-0013 for the decisions.

## Container images in CI

The `containers` job builds the API (both runtime bases), worker and web images, runs them, and drives the API through `infra/docker/smoke.sh`: sign-up, a note through the job runner, and a streamed answer that cites it, once on demo storage and once against a PostgreSQL service. Publishing `:dev` images to GHCR is opt-in: set the repository variable `PUBLISH_IMAGES=true`.
