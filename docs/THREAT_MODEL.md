# Threat model

Scope: the MVP as deployed per DEPLOYMENT.md. Assets: workspace knowledge and conversations, provider credentials, user identities and sessions, the audit trail, model configurations.

## Trust boundaries

1. Browser ↔ API (public internet; cookies + CORS).
2. API/worker ↔ PostgreSQL (two roles: `ae_identity` for identity tables only, `ae_app` under RLS for everything else).
3. Gateway ↔ model providers (outbound HTTPS with server-side credentials).
4. Model output ↔ platform (untrusted text; never executed).
5. Retrieved content ↔ model context (untrusted data placed in the prompt).

## Assumptions

- The running applications never use the PostgreSQL owner connection: queries go through `ae_app` and `ae_identity`. The owner connection string is still present in their environment today (see T17).
- Provider contracts (no-training, retention) are reflected accurately in `providers.data_handling`.
- The web origin configured in `WEB_PUBLIC_URL` is the only origin allowed credentials by CORS.
